## 1. What Is Git?

**Git is a Version Control System (VCS).**

It is software installed on your local computer that tracks changes made to your project.

### Example

Suppose you have a Python project:

```text
my-project/
├── app.py
├── config.json
└── README.md
```

You make a change in `app.py`:

```python
print("Hello")
```

Git can record the change. If the new code breaks your application, you can inspect the history and return to an earlier version instead of relying only on manual `Ctrl + Z`.

### Simple definition

> **Git = A tool that tracks changes and manages versions of your code.**

---

## 2. What Is Version Control?

Version control means keeping track of different versions of a project over time.

```text
Version 1 → Original project
Version 2 → Added login
Version 3 → Added payment
Version 4 → Fixed login bug
Version 5 → Added dashboard
```

Git records the project's history. Saved points in that history are called **commits**.

---

## 3. What Is a Commit?

A **commit** is a recorded snapshot of your project at a particular point in time.

```text
Commit 1 → Created project
Commit 2 → Added login
Commit 3 → Fixed login bug
Commit 4 → Added payment
```

You can inspect the history and use Git tools to restore earlier versions when needed.

### Remember

**Commit = Snapshot / recorded change**

A useful commit message explains what the change does:

```text
Add login validation
Fix payment timeout
Update README instructions
```

---

## 4. What Is GitHub?

**GitHub is a hosting and collaboration platform for Git repositories.**

It lets you store Git-managed projects remotely, share them with others, and collaborate.

```text
Your computer
     ↓
    Git
     ↓ push
   GitHub
```

Git manages version history. GitHub provides a remote place to host repositories and tools for collaboration.

---

## 5. Git vs GitHub

| Git | GitHub |
|---|---|
| Version control software | Hosting and collaboration platform |
| Runs on your computer and can work locally | Online service |
| Tracks changes and creates commits | Hosts remote Git repositories |
| Can work without GitHub | Commonly hosts Git repositories |
| Can be used from a terminal or GUI | Provides web-based repository and collaboration features |

### Easy way to remember

> **Git = tracks changes. GitHub = hosts and shares Git repositories online.**

---

## 6. GitHub vs Cloud File Storage

A typical cloud file-storage service mainly stores and syncs files. Git and GitHub provide repository history and collaboration features.

A Git repository includes:

```text
Project files
     +
Git information
     +
Commit history
```

Example:

```text
my-project/
├── app.py
├── config.json
├── README.md
└── .git/
```

The `.git` directory contains repository metadata and version-history information.

**Important distinction:** Git itself provides local version control. A remote GitHub repository can provide an off-computer copy and collaboration features.

## 7. Why Do We Use Git?

The notes highlight three main reasons.

### 1. Track changes

Git records project changes over time.

```text
Old code
   ↓
Make changes
   ↓
Stage changes
   ↓
Commit
   ↓
Recorded version
```

If something goes wrong, you can inspect the history and recover an earlier version.

### 2. Backup

GitHub can hold a remote copy of your repository.

```text
Local computer → Git → Push → GitHub
```

If your local computer is lost or the local project is deleted, you may be able to clone the remote repository again.

**Remember:** Git provides version control; pushing to a remote such as GitHub creates an off-computer copy.

### 3. Collaboration

Multiple developers can work on the same project and combine their changes.

Example:
- Developer A works on backend code.
- Developer B works on frontend code.
- They share changes through a remote repository and integrate them.

---

## 8. How Collaboration Works

A simplified workflow:

```text
Developer A
    ↓
Make changes
    ↓
Commit
    ↓
Push to GitHub
    ↓
 GitHub repository
    ↑
Pull latest changes
    ↑
Developer B
```

- **Push:** Send local commits to a remote repository.
- **Pull:** Fetch remote changes and integrate them into your current local branch.

Developers may work on separate branches and use pull requests to review changes before merging them. Those collaboration features are part of the broader GitHub workflow.

## 9. What Is a Repository?

A **repository (repo)** is a project managed by Git.

It contains:
- Project files
- Git metadata
- Commit history

Example:

```text
my-devops-project/
├── app.py
├── Dockerfile
├── README.md
└── .git/
```

The `.git` directory stores the local repository's internal information and history.

---

## 10. Public vs Private Repositories

GitHub repositories can be public or private.

### Private repository

Access is restricted to authorized people.

Useful for:
- Company projects
- Internal applications
- Private code
- Work that should not be publicly visible

### Public repository

The repository can be viewed publicly.

Useful for:
- Portfolios
- Open-source projects
- Demonstrating projects to employers
- Sharing code publicly

**Security reminder:** Never commit passwords, API keys, access tokens, private keys, or other secrets to a repository, even if you believe it is private.

## 11. The Basic Git Workflow

A common workflow is:

```text
Working Directory
       ↓ git add
Staging Area
       ↓ git commit
Local Repository
       ↓ git push
Remote Repository (GitHub)
```

### What each stage means

1. **Working directory:** The files you are editing.
2. **Staging area:** The changes selected for the next commit.
3. **Local repository:** Contains committed history on your computer.
4. **Remote repository:** The hosted repository on GitHub or another Git server.

When you want remote changes:

```text
Remote repository (GitHub)
       ↓ git pull
Local repository / working copy
```

### Basic commands

```bash
# Check whether Git is installed
git --version

# See the current repository status
git status

# Stage a specific file
git add README.md

# Stage all current changes in the directory
git add .

# Commit staged changes
git commit -m "Add project README"

# Push commits to the remote branch
git push

# Pull remote changes and integrate them
git pull

# View commit history
git log --oneline
```

**Note:** `git add` stages changes; it does not upload them to GitHub. `git commit` saves a local commit; `git push` sends commits to the remote.

## 12. Example: Git for an AWS Project

Imagine you are working on an AWS infrastructure project using Terraform.

```text
terraform/
├── main.tf
├── variables.tf
└── outputs.tf
```

You modify `main.tf`.

```text
Before → main.tf version 1
             ↓ edit
After  → main.tf version 2
```

A basic command sequence might be:

```bash
git status
git add main.tf
git commit -m "Update Terraform infrastructure"
git push
```

The commit records the change locally. The push sends the commit to the configured remote repository, such as GitHub.

This is useful in DevOps because infrastructure code, application code, scripts, and configuration files can be version-controlled and reviewed.
